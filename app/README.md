# 圖說紀錄產生器

> **這是吳欣儒開發的「高雄建築師公會 KAA AI WORKSHOP」示範檔案。**
>
> 課程用途，歡迎自行取用、修改。內附的示範資料（平面圖與 14 張施工查驗照片）
> 為 AI 生成的教學素材，不是實際工程紀錄。

匯入現場照片與平面圖 → 在平面圖上點出每張照片的位置 → 寫說明、畫標記 → 一鍵產出大圖報告。
工地查驗、室內設計勘查等場景都適用。平面圖置中，照片環繞四周，
每張照片以引線連到它在平面圖上的位置，說明文字在照片下方。
平面圖可匯入多張（各樓層分頁），報告每層各自成段。
紙張 A0 / A1 / A2 / A3 可選，預設 A3 橫式。

**純前端，照片不會離開這台電腦。** 唯一的程式庫（PDF 用 pdf.js）
放在 `vendor/` 本機載入、用到才載，一樣不需要網路與後端。

---

## 怎麼開始

**雙擊 `開啟圖說紀錄產生器.cmd`。** 它會在背景起一支本機靜態伺服器（`tools\serve.ps1`，
Windows 內建的 .NET `HttpListener`，不需要 Python 或 Node），然後把瀏覽器開到
<http://localhost:5178>。收工時雙擊 `關閉圖說紀錄產生器.cmd`。

重複雙擊是安全的：`tools\start.ps1` 先打 `/_health` 確認「佔用這個埠的確實是自己」，
是就沿用，被別的程式佔走就往後找埠，連監聽都起不來（公司政策擋掉）就退回直接開
`index.html`。`stop.ps1` 同樣先確認 `/_health` 才動手，而且是比對命令列找行程 ——
`HttpListener` 走 HTTP.SYS，用連接埠反查到的擁有者是 `System(4)`，踢不動也不該踢。

也可以直接用瀏覽器開 `index.html`（雙擊即可），差別只在部分瀏覽器會在 `file://` 下擋掉本機儲存；
真的被擋時介面左下角會出現提醒，功能全部照常，只是要自己按「匯出紀錄檔」保存。
要當網站掛上去的話，整個資料夾丟到任何靜態主機就好，不需要後端。

### 內建示範資料

第一次開啟（資料庫裡一份紀錄都沒有）時會自動放進兩份示範紀錄 ——
二層住宅概念平面圖的一樓與二樓，各配 6 張與 8 張施工查驗照片，
位置點、拍攝方向、說明文字都已填好，其中兩張還帶標註，開起來就能按「產生報告」。
照片與平面圖都是 AI 生成的教學素材，不是實際工程紀錄，圖框備註欄有註明。

資料放在 `sample/data.js`（約 1.8 MB，含影像），**用到才以 `<script>` 掛進來**：
不能用 `fetch`，因為雙擊 `index.html` 走 `file://` 時同源政策會擋掉，`<script>` 則照樣載得進來。
載入過就記在 `localStorage`，之後把示範資料刪掉不會自己長回來；
要重新載入按主畫面右上角的「示範資料」。整個 `sample` 資料夾刪掉也不影響其他功能。

## 主介面

開啟後看到的是**依「專案名稱」分組**的紀錄清單 —— 同一個工程或案場的歷次紀錄收在同一組，
形成完整的專案日誌。分組鍵就是每份紀錄的「專案名稱」欄位，改欄位即換組。
每組標題列有「＋ 新增紀錄」（直接歸入該專案）與「重新命名」（整組一起改）。
每張卡顯示封面照片、紀錄項目、日期、照片數，以及狀態標籤
（缺平面圖 / N 張未定位 / 已完成定位）。可以搜尋、依四種方式排序，
每張卡右上角有複製、匯出、刪除。用右上「開啟紀錄檔」讀入 `.sitelog`。

支援**拖放匯入**：照片或 `.sitelog` 直接拖進視窗即可（主介面拖照片會自動開新紀錄；
編輯畫面拖到平面圖區當平面圖、其他地方當照片）。內部拖曳（清單排序、報告互換）期間
全域拖放會被旗標擋掉 —— 否則瀏覽器把被拖項目的縮圖塞進 dataTransfer，
調個順序就會莫名多出一張照片（這正是此功能曾被移除的原因，現已用內部拖曳旗標解決）。

各份紀錄的影像完全獨立：複製會連影像一起複製，刪除某一份不會影響其他份。

## 操作流程

1. **匯入平面圖** — 「＋ 匯入平面圖」按鈕，或把圖檔拖到平面圖區。**支援影像、PDF，可匯入多張**
   （各樓層一張，圖上方變成分頁籤，籤上數字＝釘在該層的照片數）。
   PDF 多頁會問要哪幾頁（`1,3-5` 或 `all`），每頁各成一張平面圖並自動記下原始頁面尺寸。
   CAD 圖請在 AutoCAD 等軟體裡輸出成 PDF 再匯入（DWG/DXF 直接匯入已移除，原因見文末）。
2. **匯入照片** — 「＋ 匯入照片」按鈕，或直接拖進視窗。**支援影像與 PDF**（多頁 PDF 每頁變一張照片，上限 30 頁）。
   依檔名自然排序（`IMG_2` 排在 `IMG_10` 前面）。
   - **比例尺**（選用）：中欄「比例尺」→ **直接輸入原圖比例**（如 1:100）與原圖紙張（A0–A4 / 自訂寬）。
     PDF 匯入的平面圖已知頁面尺寸，第一個選項是「自動」；不確定紙張時可「改用兩點量測」。
     設定後報告可用 1:N 真實比例出圖
3. **標位置** — 在左欄選一張照片，然後點平面圖。
   - 拖曳圓點可微調位置
   - 圓點外那條虛線的把手可轉出**拍攝方向**（按住 <kbd>Shift</kbd> 不吸附 5° 格點）
   - 滾輪縮放、拖曳空白處平移
4. **寫說明、畫標記** — 右欄用畫筆／直線／箭頭／矩形／橢圓／文字標註，下面填說明文字。
5. **裁切**（需要時）— 平面圖與照片都可以裁。按「裁切」進入裁切模式，拖出範圍後套用；
   按「全圖」隨時還原。
6. **產生報告** — 按右上「產生報告」，選紙張、方向、每張圖面幾張照片、字級、版面；
   自動排的不合意就切「自由排版」直接在預覽上拖。
   最後按「列印 / 存成 PDF」，在列印對話框選「另存為 PDF」。

兩側欄位可以拖曳中間的分隔線調整寬度，雙擊還原預設；寬度會記住。

> 列印對話框裡把「邊界」設為**無**、勾選「背景圖形」，出來的 PDF 才會是滿版且線條完整。

## 報告排版

紙張可選 A0 / A1 / A2 / A3（**預設 A3 橫式**），每張圖面 4–14 張照片，超過就自動分頁。
字級有六段可調，會同時縮放說明文字與標題欄。

**多張平面圖時照片跟著它釘的那張圖分組**：每張平面圖各自成一段圖面（沒照片的樓層也會出一張圖），
圖左上角印圖名，未定位的照片排進第一組；`photo.sheet` 是「組內」頁碼。
比例尺與裁切都是每張圖各自獨立。

**真實比例出圖**：完成比例尺校正後，「比例」可選 1:50–1:500 ——
紙上寬 = 裁切後像素寬 × (實際mm/px) ÷ N，置中放置並印出 SCALE 標示；
放不下時警告需要的尺寸與實際縮到的比例，**絕不印錯誤的比例標示**。
自由排版下比例鎖定尺寸（隱藏縮放把手），換紙張時物理尺寸不變 —— 比例是絕對的。

**事務所圖框**：報告列「圖框」→ 事務所名稱、Logo（縮至 400px 的 dataURL，
隨專案 JSON 與 .sitelog 一起帶走）、最多 6 個額外標題欄位；
可設為 localStorage 預設，新紀錄自動繼承。首頁另有「使用說明」按鈕開啟圖文說明。

**照片會排在平面圖四周，不只兩側。** 版面是算出來的：程式試算「每欄幾張、上下要不要放、
照片欄寬多寬」的各種組合，挑用掉最多版面的那一種；平手時再挑平面圖框的長寬比最接近平面圖本身的。
所以遇到兩張樓層平面並排這種很扁的圖，照片就會自動排到上下，把中間的空白吃掉
（實測 A3 橫式 8 張，中間留白從 152mm 降到 0mm）。

**欄寬也在搜尋範圍內**，不是寫死的比例 —— 這是讓版面排得夠密的關鍵。
平面圖的面積在計分時給 1.25 倍權重：它是所有引線的參照點，
純比面積的話最佳解會一路把欄寬撐大、把平面圖犧牲掉。
另一個關鍵是**說明列固定薄薄一條**（列高 15%，5.5–13mm），照片吃掉其餘全部 ——
舊算法讓說明列跟著照片長到 60%，整欄一半是留白。

版面使用率（平面圖 + 照片卡佔內容區的比例）實測：

| 組合 | 最初 | 目前 |
|---|---|---|
| A3 橫 / 8 張 | 64.2% | **84.0%** |
| A3 橫 / 12 張 | 82.8% | **88.3%** |
| A3 橫 / 14 張 | — | **90.5%**（左右 4+4、上 3 下 3 環繞式） |

**排版可以完全手動接管。** 報告列的「版面」有三種：

| 版面 | 行為 |
|---|---|
| **自動** | 上面說的求解，程式決定 |
| **只放兩側** | 舊排法，照片只在左右兩欄 |
| **自由排版** | 照片與平面圖都能隨意拖放縮放、互換，程式完全不干預 |

（「自訂格位」模式已移除 —— 它的互換能力併入自由排版，介面少一種模式比較不混淆。）

### 自由排版

> 完整圖文使用說明（含可試玩的練習區）：[`docs/使用說明.html`](docs/使用說明.html)
> 教育訓練簡報（17 頁，最後一頁為三題實作練習，各附一句可直接貼給 AI 的需求）：[`docs/使用說明簡報.pptx`](docs/使用說明簡報.pptx)

切到自由排版的瞬間會把**目前自動排版的結果**原封不動抄過來當起點（實測座標逐值相同），
是接手微調而不是從空白開始。位置直接存成 mm 絕對座標 —— 和 `layout.js` 的輸出同一個座標系，
所以螢幕上拖到哪，列印出來就是哪。

- **拖曳移動**，右下角把手**縮放**。照片只調寬度、高度永遠跟著照片比例走，不會變形；平面圖鎖長寬比
- **拖到另一張照片上放開＝互換**（照片與說明一起換，目標會亮粗橘框；其餘照片一張不動）。
  按住 Alt 拖可避免觸發互換
- **對齊吸附** —— 吸附點取自內容區、平面圖、其他照片的四邊與中線，
  對齊時畫出洋紅色輔助線（實測吸附誤差 0mm）。門檻用螢幕像素換算，預覽縮多小手感都一樣
- **方向鍵微調** 1mm，Shift 一次 5mm
- **可以把照片拖到別張圖面上**（跨頁互換也行）—— 拖到預覽視窗上下邊緣自動捲動，
  目標圖面亮橘框；某頁被搬空後自動消失；每頁張數不受原本分頁數限制。
  多張平面圖時限**同一樓層的分頁**之間搬（照片跟著它釘的圖走）
- **復原 / 重做**：<kbd>Ctrl</kbd>+<kbd>Z</kbd> / <kbd>Ctrl</kbd>+<kbd>Y</kbd>（拖曳、縮放、互換、
  方向鍵微調、全部重排各算一步；快照堆疊上限 50 步，換紀錄清空）
- **改紙張尺寸時整個版面自動等比換算**（A 系列同方向縮放比例兩軸相同，
  照片高度由寬度推得、平面圖 contain 進框，所以換算不會變形；實測 A3→A1→A3 往返誤差 0）
- 引線從「卡片中心朝向位置點」那一側的邊緣拉出，照片放到任何角度都正確
- 「全部重排」把所有位置交還給自動排版重算

**引線不會交叉。** 照片依它最靠近平面圖的哪一邊，分派到那一邊；同一邊再依沿邊座標排序後對位 —
這個單調對應保證同一邊的引線不可能互相穿越。各邊容量滿了會依「第二近的邊」往外溢。

其他排版行為：

- 分頁時，**其他頁的位置點**會以灰色虛線圓標在平面圖上當參考（可關閉）
- 每張圖面的照片框大小固定，不會因為最後一頁照片較少就變大
- 照片一律 `contain` **不裁切**；垂直空間不足時改為縮減欄寬，省下的寬度自動讓給平面圖
- **外框畫在照片實際佔的矩形上，不是配給的格子上** —— 照片長寬比與格子不同時，
  框線才不會浮在照片外面變成莫名其妙的線條。說明文字也緊貼照片下緣。
- 說明文字超出卡片時自動縮小字級（最多縮到 68%），真的放不下才截斷並淡出
- 標題欄的欄位名稱與數值字級由欄高推得，且各欄依內容自動撐寬，
  所以任何紙張上日期、圖號都不會被切掉

## 存檔

- **自動存檔** — 每次改動都寫進瀏覽器的 IndexedDB，關掉分頁不會不見。右上角會顯示存檔狀態。
- **匯出紀錄檔** — 產生 `.sitelog` 檔（含所有影像與各張平面圖），可換一台電腦繼續做，或當備份。
  拖回視窗即可開啟 —— 開啟時一律新增成另一份紀錄，不會蓋掉現有資料。

資料存在這台電腦的這個瀏覽器裡，換電腦、重灌、清瀏覽器資料都會消失，
所以重要的紀錄請定期「匯出紀錄檔」。

## 一些實作上的決定

**照片會縮到長邊 2000px 存放。** 在 A1 上照片框約 130mm 寬，2000px 換算約 390 dpi，
遠高於印刷需要的 300 dpi。留著 4000px 的原始檔只會拖慢瀏覽器並塞爆資料庫。
平面圖限制放寬到 4000px，因為它要放大看細節。

**標註存成 SVG 而不是燒進點陣圖。** 所以標註可以事後修改、移動、刪除，
而且列印出來是向量，放大不會糊。座標一律正規化成 0–1，
渲染時映射到 `1000 × 1000·ar` 的單位空間 —
同一份標註在編輯區和 A1 圖面上比例完全一致，不需要任何換算。

**裁切是非破壞性的。** 只記錄一個正規化矩形，原始影像一個位元組都不動，
按「全圖」隨時還原。關鍵是標註與位置點的座標**永遠留在原圖空間**，
顯示時只把 SVG 的 `viewBox` 平移縮放到裁切區 —— 所以裁切前畫的標記不會跑掉，
裁切後再還原也不會錯位。被裁到範圍外的位置點會自動不畫引線，並在介面上提醒你有幾個。

**報告用瀏覽器列印而不是 canvas 截圖。** `@page` 直接指定實際紙張尺寸，
文字、引線、圖框全部是向量，檔案小、線條銳利、PDF 裡的文字還能被搜尋。

**內部座標一律用 mm。** `layout.js` 是純計算不碰 DOM，輸出的 mm 座標同時餵給
HTML 卡片（CSS `mm` 單位）和引線 SVG（`viewBox="0 0 W H"`），兩者天生對齊，
不需要任何測量或校正。

## 為什麼移除 DWG 直接匯入

曾以 LibreDWG（WASM，約 10MB）在瀏覽器內把 DWG 轉成線稿。拿實務圖檔驗證後移除 ——
四個真實案場的 DWG，沒有一個能可靠通過：

| 症狀 | 原因 |
|---|---|
| 「SVG 轉圖失敗」，整張圖載不進來 | 轉換器把 TEXT／MTEXT 內容原封不動塞進 `<text>`，沒跳脫 XML。圖框上常見的 `<A1>SCALE:1/100` 這種註記就讓整份 SVG 不是合法 XML |
| 匯進來是一張全白的圖 | 引擎讀得到檔案卻算不出任何圖形（viewBox 全 0），較新版本（AC1032／AutoCAD 2018）的 DWG 常見 |
| `Invalid string length`，分頁凍住 2 分鐘 | 產出的 SVG 字串撐爆 JS 字串上限（47MB 的圖產出逾 500MB SVG）；轉檔跑在主執行緒，期間畫面完全無回應 |
| 圖形只佔畫面兩成寬 | 模型空間裡的遠處物件把邊界撐大，實際平面圖被壓縮成一小條 |

前兩項可以在 `convert.js` 裡繞過（重新跳脫文字、明確報錯），後兩項要搬進 Web Worker
並自訂轉換器才有解 —— 投入與收益不成比例。CAD 圖從 AutoCAD 輸出 PDF 只要幾秒，
且 PDF 匯入本來就記得住頁面尺寸、比例尺照樣能設。
